## Verification Design

- Same-scenario A fixture: retained official 2.1.241 evidence establishes a
  UUID-shaped prompt ID in the first billing block and stable value across one
  prompt lifecycle.
- Same-scenario B fixture: a native Claude-shaped request with one caller-owned
  UUID is sent twice through each executor mode to a capturing RoundTripper.
- Control: the same request with no `cc_prompt_id` must remain absent.
- Mutation coverage: diagnostics injection and a benign payload rule must both
  run without changing the caller field; the second request must add managed
  `cc_prev_req`; CCH re-signing must be idempotent.
- Negative coverage: malformed and duplicate caller fields, when the managed
  prior-request insertion path is active, must fail before the RoundTripper.
- Falsifying observation: any changed/missing/duplicated prompt ID, changed
  billing-block path, invalid relative ordering, non-idempotent CCH, inheritance
  into an absent control, Execute/ExecuteStream divergence, or upstream call on
  a validation error falsifies the hypothesis.
- Expected result if true: every positive request reaches the capture transport
  with the original UUID exactly once, while all negative controls behave as
  specified.
- Expected result if false: focused CI fails and this card authorizes no
  production fix; a separate defect card is required.
- GitHub Actions workflow: `.github/workflows/claude-prompt-state-test.yml`
- Expected artifact paths: GitHub Actions run log plus
  `artifacts/CPA-CLAUDECODE-S5-2.3-PROMPT-ID-PRESERVATION-20260903/`.
